# 训练结果怎么看、好不好？

## 一、训练时看哪里

### 1. 控制台 / 日志

训练时会有几类输出：

| 输出 | 含义 |
|------|------|
| `训练进度: 1200/10000 手牌 (12.0%)` | 当前训练进度 |
| `训练统计 - 总手牌: 1250, 累计利润: 32.50, 当前手牌利润: 1.20, 诈唬率: 0.12, 无效下注率: 0.05` | 每 50 手牌一次的统计 |
| `评估完成: 平均利润=2.30, 胜率=58.00%, 诈唬率=0.120, 加注率=0.350, 无效下注率=0.080` | 每 `--eval-interval` 局做一次评估的结果 |
| `新最佳模型！得分: 1.3340` | 当前评估得分超过历史最佳，会保存为 best 检查点 |
| `保存 PPO 检查点: ...` / `保存检查点: ...` | 定期或“新最佳”时保存的模型文件 |
| `训练完成！总手牌: 10000`、`最终评估: {...}` | 训练结束时的总结和最后一次评估 |

日志文件在项目下的 `logs/` 目录，例如：`logs/poker_ai_YYYYMMDD_HHMMSS.log`。

### 2. 训练结束后生成的文件

- **检查点目录**（默认 `./checkpoints/`）  
  - PPO：`agent_ppo_<手数>` 或 `best_agent_ppo_<时间戳>`（对应 `.actor.weights.h5`、`.critic.weights.h5`、`_state.pkl`）。  
  - 有“新最佳”时会有 `best_agent_*`，通常用来做最终评估和上线。
- **训练总结**：`checkpoints/training_summary_YYYYMMDD_HHMMSS.json`  
  - 包含：总耗时、手数、参数、大致吞吐（手/秒）等。

## 二、关键指标：什么叫“好”

评估时（包括训练中每段评估和单独跑 `eval`）会得到下面这些指标，可以这样理解“好不好”：

### 1. 最直接：**平均利润**（avg_profit）

- **含义**：主 AI（Main_AI）在评估的每局结束时，相对初始筹码的平均盈亏（筹码数）。
- **怎么看**：  
  - **> 0**：整体在赢钱，数值越大越强。  
  - **≈ 0**：和对手打平，可能还在学、或对手也强。  
  - **< 0**：在输钱，要么训练不够，要么超参/奖励要调。
- **注意**：评估只有 100 局（默认 `--num-eval-games`）时，波动会比较大，可多跑几次或增大 `--num-eval-games` 再看趋势。

### 2. 胜率（win_rate）

- **含义**：主 AI 在评估局数里“拿下该局”的比例（不是每手牌都赢，而是这一局结束时是赢家）。
- **粗略参考**：6 人桌随机水平约 1/6≈16.7%；能稳定在 **25%～35%+** 且平均利润为正，通常说明比随机/弱对手强。

### 3. 综合得分（current_score）

- 训练里用来选“是否保存为最佳”的公式是：**current_score = avg_profit × win_rate**。
- 所以：**平均利润高、胜率也高** → 得分高 → 会更多次触发“新最佳模型”保存。

### 4. 策略健康度（辅助看）

| 指标 | 含义 | 参考 |
|------|------|------|
| **诈唬率** (bluff_rate) | 在加注/跟注中“弱牌却进攻”的比例 | 有一定诈唬（如 0.1～0.25）比从不诈唬或乱诈唬更合理 |
| **加注率** (raise_rate) | 在非弃牌决策里加注的比例 | 太低压制力不足，太高容易送钱，需结合利润看 |
| **无效下注率** (invalid_bet_rate) | 加注中“明显不合理”的比例 | 越低越好；偏高说明还在乱打 |

这些主要用来判断“是不是在学策略”，而不是单独判断强弱；**最终仍以平均利润和胜率为准**。

## 三、单独做一次正式评估

训练完后，用保存的**最佳检查点**做一次更大规模的评估，结果更稳：

```bash
# 用最佳 PPO 模型，评估 500 局，结果写到 eval_results.json
python train.py --mode eval --model-type ppo \
  --model-path ./checkpoints/best_agent_ppo_20231120_120000 \
  --num-eval-games 500 \
  --eval-output eval_results.json
```

或使用 `evaluate.py`（若项目里有）：

```bash
python evaluate.py --model-path ./checkpoints/best_agent_ppo_xxx --num-games 500
```

看结果：

- **控制台**：会打印平均利润、胜率、总利润、获胜次数等。
- **eval_results.json**：完整数值，方便对比不同模型或不同训练阶段。
- **eval_results.txt**：同一份结果的文本报告（和 README 里评估报告格式一致）。

**“好不好”的简单判断**：  
在 500 局、对手设置一致的前提下，**平均利润明显 > 0** 且 **胜率 > 20%**，可以认为这一版训练结果是“好的”；再结合诈唬率/无效下注率没有异常高，就说明策略也比较健康。

## 四、训练曲线与稳定性（可选）

- `performance_history` 会按每次评估把结果 append 进去，并随检查点保存在 `_state.pkl` 里。  
- 若要画“平均利润 / 胜率随训练进度变化”的曲线，可以用保存的 `checkpoints/*_state.pkl` 里 `performance_history` 或训练日志解析出每次评估的 `avg_profit`、`win_rate` 再绘图。  
- 若**平均利润随训练轮数逐渐上升并趋于稳定**，说明训练有效；若长期负或剧烈震荡，可以调学习率、`--ppo-clip`、`--num-hands` 或奖励设计。

---

## 五、一句话总结

- **训练时**：看控制台/日志里的 **平均利润**、**胜率** 和是否经常出现 **“新最佳模型”**。  
- **训练后**：用 **best 检查点** 跑一次 **500 局评估**，看 **eval_results** 里的 **平均利润 > 0**、**胜率 > 20%**，再结合诈唬率/无效下注率没有异常，就可以认为这一版训练结果**是好的**。
