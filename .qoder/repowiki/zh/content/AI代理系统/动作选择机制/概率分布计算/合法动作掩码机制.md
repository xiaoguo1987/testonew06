## 简介

本文档深入解析了德州扑克AI系统中的合法动作掩码机制。该机制是AI决策系统的核心组成部分，负责在每一步游戏中动态生成合法动作的掩码向量，确保AI只能选择符合德州扑克规则的动作。本文将详细解释_get_legal_action_mask函数的工作原理，涵盖5种动作类型（弃牌、跟注、加注x2、加注x4、全下）的合法性判断逻辑，以及德州扑克规则在代码中的具体实现。

## 合法动作掩码机制详解

### 动作类型定义

合法动作掩码包含5个维度，对应5种不同的动作类型：

| 维度 | 动作类型 | 数值含义 | 描述 |
|------|----------|----------|------|
| 0 | Fold | 1.0 | 弃牌，放弃当前手牌 |
| 1 | Call | 1.0 | 跟注，匹配当前下注额 |
| 2 | Raise x2 | 1.0 | 加注到当前下注额的2倍 |
| 3 | Raise x4 | 1.0 | 加注到当前下注额的4倍 |
| 4 | All-in | 1.0 | 全部筹码下注 |

### 合法性判断逻辑

#### 基础约束条件

1. **玩家状态约束**
   - 如果玩家已弃牌或已全下，则只能选择弃牌
   - 这通过简单的布尔检查实现

2. **跟注合法性**
   - 跟注金额 = max(0, current_bet - player.bet)
   - 只要跟注金额不超过玩家筹码，跟注就是合法的
   - 当跟注金额为0时，相当于检查（pass）

3. **加注合法性**
   - 加注金额必须大于当前下注额
   - 加注金额必须满足最小加注要求
   - 加注金额不能超过玩家可用筹码

#### 最小加注额规则

最小加注额遵循德州扑克标准规则：

```mermaid
sequenceDiagram
participant Game as PokerGame
participant Mask as LegalActionMask
participant Player as Player
Game->>Mask : 计算最小加注额
Mask->>Mask : current_bet = max(game.current_bet, game.big_blind)
Mask->>Mask : min_raise_total = max(game.current_bet * 2, game.big_blind)
Note over Mask : 最小加注额 = max(当前下注额的2倍, 大盲注)
Mask->>Player : 检查玩家筹码
Player-->>Mask : player.stack
Mask->>Mask : 验证加注金额 <= player.stack
```

### 规则约束的具体实现

#### 大小盲注处理
- 小盲注位置：dealer_pos + 1
- 大盲注位置：dealer_pos + 2
- 盲注必须满足玩家筹码要求

#### 跟注规则
- 跟注金额 = max(0, current_bet - player.bet)
- 如果玩家筹码不足，自动转换为全下

#### 加注规则
- 最小加注额 = max(current_bet × 2, big_blind)
- 加注金额必须大于当前下注额
- 加注金额不能超过玩家可用筹码

### 掩码数值含义

- **1.0**：动作合法，可以执行

### 全下状态处理

当玩家只剩下最后一点筹码时，系统会自动处理全下状态：

```mermaid

StackZero --> |否| NormalFlow["正常流程"]
MarkAllIn --> ForceFold["强制弃牌掩码"]
ForceFold --> ReturnMask["返回掩码"]

```

### 跟注额为0的处理

当current_bet等于player.bet时，跟注金额为0，这相当于检查：

- **数值含义**：0.0表示动作合法但不需要支付额外筹码
- **语义理解**：这是检查（check）动作的数学表达

### 最小加注额边界情况

系统正确处理最小加注额的各种边界情况：

- **current_bet = 0**：最小加注额 = big_blind
- **current_bet > 0**：最小加注额 = max(current_bet × 2, big_blind)
- **all-in情况**：确保全下金额不超过玩家可用筹码

## 故障排除指南

### 常见问题诊断

#### 掩码全为0的问题

**症状**：所有动作掩码都为0.0

**可能原因**：
1. 玩家状态异常（is_active = False）
2. 玩家筹码不足
3. 游戏状态数据损坏

**解决方案**：
1. 检查玩家状态验证逻辑
2. 实施回退机制
3. 添加错误日志

#### 加注金额计算错误

**症状**：加注金额不符合预期

**可能原因**：
1. 最小加注额计算错误
2. 玩家可用筹码计算错误
3. 类型转换问题

**解决方案**：
1. 仔细检查数学运算
2. 添加边界值测试
3. 实施数值验证
